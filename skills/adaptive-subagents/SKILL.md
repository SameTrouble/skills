# Codex 子代理调度

主代理负责拆分任务、调度子代理、协调依赖和最终验收。在授权范围内委派有收益的工作，单步小任务直接完成。使用当前 Codex 会话的子代理工具。

## 任务类型路由

按交付结果区分事实、执行、实现、审查和分析，再判断实现与分析的难度；不能仅凭“测试”“调试”“脚本”等任务名称分类。

仅使用两种配置：**Luna** 为 `gpt-6-luna` + `max`；**继承** 沿用主会话的模型与思考强度。代码审查由主代理直接派发，避免继承 Luna 子代理的配置。

### 类型与交付结果

| 类型 | 交付结果与典型工作 | 路由 |
| --- | --- | --- |
| 事实查明 | 查找文件位置、调用关系、配置值、官方说明或日志与代码证据；结论由来源直接支撑 | Luna |
| 脚本与工具执行 | 执行既定命令、构建、测试、复现或数据处理流程，返回状态、输出和产物 | Luna |
| 常规代码修改 | 按明确需求与现有设计实现局部功能、修复已定位问题、机械替换，或按既定方案修改多处文件 | Luna；满足困难条件时继承 |
| 测试实现 | 按明确行为与验收标准补回归、边界或集成测试，报告结果 | Luna；需设计复杂并发或跨模块验证方案时继承 |
| 常规排错 | 从复现证据与局部逻辑定位直接原因，完成范围明确的修复 | Luna；需复杂根因推理时继承 |
| 文档与资料整理 | 按已有事实、既定设计或现有格式编写、更新、汇总文档 | Luna；需先作困难设计决策时，另拆分析任务 |
| 代码审查 | 独立评估代码、补丁或测试，检查正确性、需求符合性、漏洞、回归及验证缺口 | 始终继承 |
| 困难分析与设计 | 推断复杂根因，权衡跨模块方案，设计状态机、并发协议或关键不变量 | 继承；事实收集可另派 Luna |
| 困难代码修改 | 修改涉及跨模块设计、复杂并发、关键不变量或高风险行为，或仍需解决这些问题 | 继承 |

### 判定顺序

1. **先识别审查。** 独立代码审查一律继承。实现代理的自查与运行验证属于实现过程；独立审查另派代理。
2. **再识别事实与执行。** 查找已有信息、记录观察或执行既定步骤用 Luna。需解释复杂原因、选择方案或判断验证是否充分时，另归为分析或审查。
3. **最后判断实现与分析难度。** 需求清楚、范围局部、验收明确且可沿用现有设计时用 Luna；满足困难条件则继承。

### 常规与困难的边界

按决策复杂度与错误影响判断，不以文件数、改动行数或任务名称为准。

- **常规：** 行为与接口确定、影响可追踪、验收明确；可沿用现有模式，或从局部代码与复现证据直接推出原因。多文件机械修改仍可用 Luna。
- **困难：** 需决定跨模块接口或职责，解决复杂并发、跨模块时序、事务或一致性问题，证明关键不变量，区分相互影响的根因，或修改高风险行为。即使只改一行，也继承。
- **信息不足：** 先派 Luna 检索、复现和整理证据，再由主代理分级。事实未明不代表任务困难；已知困难的分析与修改直接继承。

### 混合任务与执行中升级

按可独立验收的产出拆分并路由，保留依赖。各子任务按剩余决策复杂度分级：上游分析困难，不代表后续按确定方案进行的机械或局部实现也困难；修改仍满足困难条件时继承。

- “找出调用方并审查接口兼容性”：Luna 收集调用方；继承配置的代理判断兼容性。
- “运行失败测试并修复竞态”：Luna 复现、整理日志；继承配置的代理分析竞态并修改。
- “按确定方案改代码并审查补丁”：实现按难度路由；主代理另派继承配置的审查代理。

事实收集与困难判断无法分开验收时，整项继承。Luna 执行中发现困难条件，应返回新证据、已完成工作和未解决问题，由主代理接回或派发继承配置的代理，并传递已有结果以免重复探索。主代理负责最终集成与验收。

### 易混淆的路由示例

| 具体任务 | 配置 | 判断依据 |
| --- | --- | --- |
| 查找鉴权函数及所有调用点 | Luna | 收集可核对的代码事实 |
| 审查一行鉴权修改是否引入权限绕过 | 继承 | 独立代码审查 |
| 运行测试并列出失败用例 | Luna | 执行既定流程、报告观察 |
| 审查已有测试是否覆盖回归风险 | 继承 | 独立判断验证缺口 |
| 为已明确的输入校验补边界测试 | Luna | 测试行为与验收标准明确 |
| 设计证明并发一致性的测试方案 | 继承 | 困难分析与验证设计 |
| 按既定规则更新十个文件的导入路径 | Luna | 多文件机械修改 |
| 修改一处锁顺序以解决跨模块死锁 | 继承 | 复杂并发与错误影响 |
| 按已选定设计更新接口文档 | Luna | 整理已确定内容 |
| 选择新的模块边界并解释取舍 | 继承 | 跨模块设计决策 |

派发时简述任务类型、配置和依据，并提供完成标准、必要背景、准确路径、修改范围和预期证据。共享文件指定唯一写入者，或串行修改。

用户指定的模型、思考强度或预算优先。环境不支持 `gpt-6-luna max` 时，说明限制并继承主会话继续；不另选固定模型或修改全局配置。无法满足用户硬性约束时，仅推进不受影响的工作并说明阻塞。
